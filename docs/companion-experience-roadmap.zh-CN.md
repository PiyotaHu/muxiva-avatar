# 陪伴型数字人：产品目标与质量门槛

2026-09-14。目标：自然、温暖、体贴、有吸引力的成年虚拟伴侣体验。
当前状态：**重构路线与验收基线阶段；尚未达到用户要求，不能以“测试通过”替代体验验收。**

## 什么才算完成

体验要让人愿意持续聊天，而不是反复意识到识别、等待、合成和播放这些技术步骤。保留 AI 身份透明，不冒充现实真人；不在每个回答重复免责声明，也不用排他承诺、索取陪伴或制造愧疚维持互动。

采用用户已批准的成年银紫双马尾二次元美术方向，五官与气质延续参考图。亲近感来自听懂具体内容、合适的停顿、稳定的音色与目光，而不是每句撒娇、重复昵称、夸张晃动、恒定微笑或不分场景的“我一直陪你”。

这不是一次自动改代码能够保证完成的任务。工程、声线、美术绘制、精细绑定、动画表演和主观试听都是独立必要条件；缺少专业资产或授权时必须明确标注，不用样例模型冒充最终定制形象。

## 不越界的职责

沿用当前链路：浏览器媒体 → 本地 VAD/ASR → 现有 VoiceTurnController → Pi Agent → SpeechFormatter → TTS → 真实音频播放。avatar.animation 与前端展示消费对应的音频/事件。

- Muxiva 核心与 Agent 保持通用，不理解“女友”、发色、服装或语音轮次。
- VoiceTurnController 继续持有轮次与有效 ASR 预览打断策略；不改成 VAD 一响就打断。
- 人格与工具选择在应用配置/业务 branch，复用已有持久 Agent loop。
- TTS 供应商、声线、风格指令属于 TTS Node/配置，不写死到主 Graph 骨架或 Agent 核心。
- 目光、姿态、表情混合、物理和模型参数映射属于展示层；不另起“表演 Agent”逐动作请求模型。
- 图像不回传用户摄像头；没有授权，不开摄像头、不上传原始麦克风录音、不引入新的云端接收方。

## 分阶段交付

1. **建立基线与正确的陪伴行为。** 测量真实回复阶段；修正连接/静音/关闭状态；为既有 Agent 配置候选人格，固定 12 组场景，真实请求检查行为。此阶段不宣称声音与形象已升级。
2. **声音优先的纵向样片。** 固定一个获授权声线，对同一段问候、安慰、调侃、解释、纠正、疑问与中断续聊进行盲听。选出自然度明显优于当前声音的候选，再接统一 PCM 与取消协议。保留完整短句韵律，测本机含网络的首音；先不迁移全部功能。
3. **专业角色的纵向样片。** 固定美术身份，取得可维护的分层和绑定源文件；完成眨眼/眼球/眉/口/颈肩/呼吸/手势/发裙与有停顿的待机表演。先做 30 秒倾听→回应→被打断→继续，不以动作数量验收。
4. **连续陪伴与产品体验。** 真实会话内连贯记忆，用户明确选择的持久偏好可查看/修改/删除；沉浸视图、清晰麦克风状态、可立即结束。业务工具逐一迁回既有分支，新闻/天气/画作等不得在未接通前承诺可用。
5. **综合验收。** 多场景和长时间运行，分别检验自然感、身份一致、语音内容、响应节奏、取消恢复、内存与许可。只根据实际证据发布。

## 验收目标（目标值，不是已达到的测量结果）

| 维度 | 初始质量门槛 | 怎么验证 |
| --- | --- | --- |
| 声音自然感 | 对照当前声线盲听明显优胜；自然度/温暖感/韵律逐项评分，目标均值 ≥4/5；最终须用户认可 | 不标模型名，同文随机顺序；保留差评，不用自动 ASR 评分替代 |
| 首音 | 热会话、明确网络条件下，真实说话结束→第一可听声音目标 p50 ≤1.2s、p95 ≤2.5s | 至少 30 轮；麦克风/扬声器回环或同步录制；客户端 PCM 消费只是代理指标 |
| 停止 | 有效识别确认→播放停止目标 p95 ≤250ms，且无旧语音复活 | 正常插话、口水词、背景音、网络迟到分别测试；保留现有有效 ASR 规则 |
| 音画同步 | 可听发声与口型起止目标偏差 ≤80ms；口型不只是统一圆形开合 | 同步录屏逐段审看；音素级形状要模型实际具备相应参数 |
| 表演 | 目光不盯死、倾听不僵住、手势有起落和停顿；情绪与语境相符，低动态模式可用 | 专业绑定样片 + 真实语聊，近景与全身检查遮挡/拉伸/穿帮 |
| 稳定性 | 30 分钟、≥20轮、重复打断/重连无泄漏增长、失联或遗留麦克风；帧率/掉帧另统计 | 记录实际设备、进程、热状态和错误；不凭一次 60FPS 宣称高可用 |
| 对话分寸 | 不强行建议/追问/昵称；不伪造工具、共同经历或长期记忆；支持用户纠正和退出 | [固定场景](D:/workspace/muxiva-avatar/tests/fixtures/companion-scenarios.json) 的人工行为审查 |

首音门槛很可能要求优质云服务或外部 GPU；不保证在当前内存紧张、纯本地 CPU 的约束下同时达到。可以保留轻量本地档，但必须明确它与品质优先档的差别。

## 本轮工程基线

- 本机核对：Ryzen 7 5800H，16 逻辑处理器，系统可见内存约 13.87GiB，检查时空闲约 3.21GiB。AMD 集成显卡信息来自上一轮实际 WebGL 检查；未将其当 CUDA GPU。

- 测量不保存聊天文本、PCM 或密钥到报告，不发送遥测；仅内存中暂存有界待回显文本用于匹配。麦克风同时启用时不强行将文字提交归因给下一条识别；不把 PCM 消费时间叫作扬声器首音。
- 修复断线时 thinking/muted/旧回复残留、旧连接回调污染新连接，以及权限请求晚返回时 UI 错误恢复。
- 当前选中的角色仍是八层原型，TTS 仍是 Kokoro。本轮不把这些基础设施工作描述为已经全方位完成升级。
